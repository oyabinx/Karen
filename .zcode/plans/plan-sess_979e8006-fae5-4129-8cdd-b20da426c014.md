Membuat dokumentasi perencanaan untuk aplikasi **Karen** (sistem peminjaman kendaraan dinas self-service, Laravel Monolith + MySQL) di folder `docs/`:

## Struktur file yang dibuat

```
docs/
├── product.md        → visi, profil pengguna (3 role), lingkup fitur, alur bisnis
│                       (booking, pengembalian, auto-return), aturan/pembatasan bisnis
├── tech.md           → stack (Laravel 12, MySQL, Tailwind), arsitektur, skema database,
│                       kebijakan keamanan, scheduler auto-return
├── structure.md      → struktur folder aplikasi lengkap + penjelasan tiap direktori
├── taskplan.md       → roadmap implementasi bertahap dengan checklist per fase
└── feature/
    ├── autentikasi.md          (login email+password, logout, middleware role)
    ├── manajemen_user.md       (CRUD user admin, assign role/bidang/seksi)
    ├── organisasi.md           (CRUD 5 bidang & seksi, seeder awal)
    ├── manajemen_kendaraan.md  (CRUD mobil, status, jadwal maintenance - pengurus)
    ├── peminjaman.md           (cek ketersediaan rentang tanggal, booking ≤3 hari,
    │                            alamat + keperluan, aturan 00:00–24:00)
    ├── pengembalian.md         (tombol kembalikan, form keluhan unit, status available)
    ├── pengembalian_otomatis.md (scheduler harian auto-return lewat jatuh tempo)
    ├── dashboard.md            (dashboard admin/pengurus/pegawai)
    ├── laporan.md              (laporan penggunaan + riwayat - pengurus)
    └── profil.md               (ubah profil, nomor HP wajib)
```

## Poin-poin desain utama yang didokumentasikan

- **Ketersediaan mobil**: booking disimpan sebagai `start_date` + `end_date` (DATE, satuan hari penuh 00:00–24:00). Mobil tersedia jika tidak ada booking aktif yang overlap (`start_date <= akhir AND end_date >= mulai`), termasuk tidak sedang maintenance.
- **Aturan 3 hari**: durasi maksimal 3 hari kalender termasuk Sabtu/Minggu; booking hari-H tetap dihitung mulai 00:00 hari itu.
- **Auto-return**: Laravel Scheduler harian (00:01) mengubah status booking lewat jatuh tempo menjadi `dikembalikan` (tercatat otomatis) dan mobil kembali available.
- **Keluhan**: form keluhan saat pengembalian; jika ada keluhan, mobil ditandai `perlu_diperiksa` dan muncul di daftar pengurus.
- **Role**: admin (user & organisasi), pengurus (kendaraan, maintenance, monitoring, laporan), pegawai (booking & pengembalian). Booking langsung terkonfirmasi tanpa approval.

Semua dokumen ditulis dalam Bahasa Indonesia. Tidak ada kode aplikasi yang dibuat pada tahap ini — hanya dokumentasi.
